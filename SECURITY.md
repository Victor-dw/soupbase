# Reporting security issues

Please do not include API keys, management links, private puzzles or production data in public issues.

If this repository has GitHub private vulnerability reporting enabled, use **Security → Report a vulnerability**. Otherwise, ask the maintainer for a private reporting channel without publishing exploit details. Include the affected version, impact and minimal reproduction steps with synthetic data.

This project is pre-1.0. Fixes target the latest source version; older releases do not have a separate support commitment.

See [the security model](docs/security.md) for credential and deployment boundaries.
